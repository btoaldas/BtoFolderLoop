## Reproduce release verification

In a new empty test directory:

```sh
gh release download v0.1.0 --repo btoaldas/BtoFolderLoop
shasum -a 256 -c SHA256SUMS
ditto -x -k BtoFolderLoop-0.1.0-macos-arm64.zip .
codesign --verify --deep --strict BtoFolderLoop.app
```

For UI validation, create a new artificial tree containing an empty three-level chain, a normal file, a hidden file, a symbolic link to an empty directory within the tree, and an empty application package. Use a separate test database through `BTOFOLDERLOOP_TEST_DATA`. Verify cancel first, then one pass, then cascade; compare file hashes and directory identities with the pre-test inventory. Do not use a valuable archive for smoke tests.

## Limits and next stage

This is a preview for Apple Silicon, targeting macOS 14+. The binary is locally signed ad hoc and **not notarized by Apple**. The CLI download was tested for package integrity and runtime behavior; this does not establish a Gatekeeper-approved first launch from a browser download. No quarantine flags or system security settings were changed.

The folder chooser was exercised end to end; cross-application drag-and-drop and a broader macOS/cloud-provider matrix remain explicit follow-up validation. Concurrent writers and references outside the selected tree cannot be fully controlled. See README and SECURITY.md.

Raw UI evidence and local databases are intentionally excluded from Git. The sanitized milestone is ready for a separately authorized knowledge-vault snapshot; that export remains pending. No user files were cleaned and Trash was not emptied.
