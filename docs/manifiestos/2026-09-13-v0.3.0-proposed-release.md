# Proposed v0.3.0 publication and installation

Status: prepared locally; publication and replacement of the installed application have not been performed or newly authorized for this scope.

## Exact scope

- Repository: existing public `btoaldas/BtoFolderLoop`; branch `main`; new tag/release `v0.3.0` as preview. Retain v0.1.0/v0.2.0 and their assets unchanged.
- Code: durable live history, configurable diagnostic/history retention and backups; signed one-click update footer; multiple folders/Finder aliases/symlinks with duplicate and nested-root protection.
- Assets: Apple Silicon ZIP, SHA256SUMS, source-commit BUILD-INFO and signed ARM64 appcast. Verify freshly downloaded assets before publishing the identical feed under `updates/` on the default branch.
- Optional local installation, separately explicit in the approval: close the old application only when no cleanup/scan is active, preserve an identified copy of the existing application, install the validated bundle and verify launch/version/data migration. Do not interfere with an active operation.

## User data and limits

Application support data remains outside the updated bundle. The first schema-1 opening by 0.3.0 creates an online SQLite backup before migration. Default retention is 30 diagnostic days / 10 MiB and 180 days for consistent completed history; protected incomplete/error records and migration backups remain. No application update or log expiration deletes source files/folders or empties Trash.

The installed public 0.2.0 needs a manual first installation of the updater-enabled version. Bundles remain ad-hoc signed and not Apple-notarized. Synthetic local tests do not establish every macOS/provider combination or a warning-free first launch on another Mac.

## Verification and rollback

Require passing source privacy checks, automated/synthetic native tests, package signature/resource/hash verification, matching source commit and signed archive/feed validation. Check live operation status before any replacement. After publication, require successful CI and fresh public downloads; after authorized installation, verify the actual running app and migrated data independently.

Do not automatically overwrite a newer journal with a migration backup. A rollback requires compatibility review and preserving all subsequent records. Do not withdraw public assets, rewrite tags/history or purge temporary evidence silently. If authority is not supplied, retain the tested local code/package and the unchanged installed application.
